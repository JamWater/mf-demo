
## mf-demo 微前端路由白屏修复
- 问题：/user/profile 下点"账号设置"跳到 /user/profile/settings，内容区空白
- 根因：react-router v6 通配路由 `/user/*` 内的相对链接按当前完整 URL 解析，而非路由前缀；UserCenter 的 basePath 参数未由 host 注入
- 修复：host/src/App.tsx 中给 RemoteUserCenter 传 basePath="/user"，子应用内部导航变为绝对路径 /user/profile、/user/settings
- 后续：Profile.tsx 改为消费 host/useUserStore（MF 共享 zustand 单例）后出现两类问题：
  1) host/tsconfig.json 的 include 直接引用了 remote 的 Profile/Settings.tsx 但未包含 remote/src/host-typings.d.ts → TS2307/TS7006（已告知用户方案，待其确认）
  2) 运行时 TypeError：localStorage 'user-storage' 持久化了旧结构 userInfo（缺 permissions 字段），persist 恢复后 Profile 里 userInfo?.permissions.join 抛错 → 已把该行改为 userInfo?.permissions?.join 防御性写法；根治需清 localStorage 或给 persist 加 version+migrate
- 架构规划讨论：用户希望把 mf-demo 往「业务能力 / 架构解耦 / 工程化 / 高级特性」四个维度推进，当前已完成维度一（zustand 单例跨应用状态共享 + persist）。
- 已指出的核心架构问题：host 与 remote 双向联邦（host remotes remote/UserCenter，remote remotes host/useUserStore）存在循环依赖与强耦合，应改为契约下沉或 props 注入。
